# АРХИТЕКТУРА ПИЛОТА (MVP) И СТРАТЕГИЯ УСИЛЕНИЯ ЗАЩИТЫ FAZAZERO (RED TEAM X10)

> **Дата фиксации:** Октябрь 2026  
> **Статус документа:** Утверждено разработчиком и фаундером. Все предыдущие редакции сохранены.  
> **Продукт:** Fazazero (КЗ-Эксперт) — B2B веб-сервис расчета токов КЗ и петли «фаза-ноль» по ГОСТ 28249-93 и ПУЭ-7 (п. 1.7.79) с генерацией томов по ГОСТ 2.105-95.

## ЧАСТЬ 1. ОКОНЧАТЕЛЬНЫЙ ВАРИАНТ АРХИТЕКТУРЫ ДЛЯ ПИЛОТА (MVP 2026)

### 1.1. Стратегическое обоснование: Lean-подход («Рынок коварен»)
Главная аксиома продуктового бизнеса: **нельзя тратить месяцы на разработку военной криптозащиты до тех пор, пока рынок не подтвердил спрос живым рублем**.
- Рынок САПР и B2B-проектирования консервативен. Сервис может столкнуться с неожиданными барьерами (например, проектировщикам важнее экспорт в AutoCAD, чем Word, или они потребуют другой стандарт).
- Главная цель Пилота — **быстрая проверка продуктовой гипотезы (Product-Market Fit)**:
  * Проверить конверсию из бесплатной экранной экспресс-диагностики в покупку чистового тома за 990 ₽;
  * Собрать 100–300 реальных нестандартных кабельных журналов Excel от живых институтов для дообучения парсера;
  * Получить первый пул лояльных проектировщиков и отзывы для сарафанного радио в Telegram-сообществах.

### 1.2. Доменная стратегия: Немедленный переход на `fazazero.ru`
Регистрация и выделение отдельного домена `fazazero.ru` (вместо работы в подпапке `rukrediti.ru/fazazero/`) решает две критические проблемы:
1. **Обход корпоративных файрволов:** В проектных институтах, НИИ и холдингах доступ в интернет фильтруется корпоративными шлюзами (UserGate, Kaspersky Security Web Gateway, Fortinet). Домен `rukrediti.ru` категоризируется как *«Финансы / Кредиты / Займы»* и наглухо блокируется сисадминами. Домен `fazazero.ru` относится к категории *«IT / САПР / Инженерия»* и свободно открывается на рабочих местах.
2. **Инженерное B2B-позиционирование:** Главные инженеры проектов (ГИПы) и начальники отделов ЭОМ видят строгий профессиональный САПР-инструмент без сомнительных ассоциаций с кредитным порталом.

### 1.3. Архитектура Пилота (100% Client-Side PWA Zero-Server)
```
┌─────────────────────────────────────────────────────────────────────────┐
│                        РАБОЧАЯ СТАНЦИЯ ИНЖЕНЕРА                         │
│                                                                         │
│  [Браузер / PWA Desktop: Chrome / Yandex / Edge / Safari]               │
│                                                                         │
│  ┌───────────────────────┐         ┌─────────────────────────────────┐  │
│  │    src/ui/app.ts      │         │       src/core/                 │  │
│  │ (UI, Drag-and-Drop,   │ ──────► │ calculator.ts (ГОСТ 28249-93)   │  │
│  │  фильтры, анимации,   │ ◄────── │ remediation.ts (Smart Auto-Fix) │  │
│  │  сворачивание плашек) │         │ docxGenerator.ts (ГОСТ 2.105)   │  │
│  └───────────────────────┘         └─────────────────────────────────┘  │
│              │                                      │                   │
│              ▼                                      ▼                   │
│     [Экран: Бесплатно]                  [Word .docx прямо в RAM]         │
│     Токи, графики, ошибки               (Официальный том пояснительной) │
└─────────────────────────────────────────────────────────────────────────┘
```
* **Стек:** TypeScript, скомпилированный через `esbuild --minify` в `public/js/core.js` и `public/js/app.js`.
* **Автономность:** `Service Worker` кеширует статику в `CacheStorage` на SSD. Приложение работает при отключенном интернете.
* **Базовая защита Пилота:**
  1. Минификация имен переменных и схлопывание структуры кода через `esbuild`;
  2. Базовый Domain Lock: проверка запуска на `fazazero.ru` / `localhost`;
  3. Демо-режим Word: по умолчанию генерируется документ с диагональным водяным знаком *«ДЕМОНСТРАЦИОННАЯ ВЕРСИЯ. НЕ ДЛЯ ЭКСПЕРТИЗЫ»*.

## ЧАСТЬ 2. RED TEAM АУДИТ И МОДЕЛЬ УГРОЗ

Анализ уязвимостей архитектуры глазами атакующего конкурента / полупрофессионала:

### 2.1. Почему наивный Wasm и JS ломаются за 15–30 минут
1. **Декомпиляция WebAssembly:** Использование открытого пакета `wabt` (`wasm2wat engine.wasm -o engine.wat`) превращает бинарник Wasm в текстовый ассемблер.
2. **NOP-патчинг:** Функция проверки лицензии `$verify_ticket` локализуется поиском. Замена ветвления `br_if` на `nop` или принудительный возврат `i32.const 1` отключает водяные знаки навсегда.
3. **Monkey-Patching в JS:** Любые проверки флагов на клиенте обходятся через консоль DevTools за пару строчек.

### 2.2. Почему нельзя отправлять проект на сервер (Табу на серверный парсинг)
- **Служба Безопасности (СБ) режимных НИИ:** Ни один проектный институт (объекты Газпрома, Росатома, РЖД, больницы) не пропустит трафик с силовыми схемами объекта наружу. Сниффер Wireshark сразу покажет утечку данных, что приведет к служебному расследованию и запрету сервиса.
- **Юридическая ответственность:** Хранение схем электроснабжения на сервере налагает обязательства по защите коммерческой тайны, риски по 152-ФЗ и персональную ответственность разработчика в случае аварий на объектах.

### 2.3. Вектор Replay-атаки (Раздача билета в чаты)
Если сервер подписывает билет только по времени (`{ exp: +24h }`), один оплативший инженер Вася выкладывает билет в Telegram-чат проектировщиков на 4 000 человек. Все участники бесплатно генерируют сотни чужих проектов.

## ЧАСТЬ 3. ВАРИАНТЫ УСИЛЕНИЯ ЗАЩИТЫ ПОСЛЕ УСПЕШНЫХ ПРОДАЖ

Благодаря строгой модульной архитектуре (`src/ui/` полностью отвязан от `src/core/`), перевод сервиса на усиленные уровни защиты выполняется без переписывания интерфейса.

### ВАРИАНТ 1. Гибридный шлюз генерации Word (Zero-Knowledge Docx Gateway)
> **Срок внедрения:** 1–2 рабочих дня  
> **Степень защиты:** Абсолютная (100%)  
> **Где применяется:** Массовый онлайн SaaS (розничные продажи по 990 ₽)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        БРАУЗЕР КЛИЕНТА (ОФЛАЙН)                        │
│                                                                        │
│ 1. Бесплатный расчет токов КЗ, подбор сечений и графики (на клиенте)   │
│ 2. Клиент жмет «Купить официальный том за 990 ₽»                       │
│ 3. Браузер отправляет на микросервер ТОЛЬКО обезличенные цифры:         │
│    POST /generate-docx                                                 │
│    { "token": "PAY-8831", "lines": [{ "ikz": 420, "c": "C16" }, ...] } │
│    (НИКАКИХ названий объектов, адресов и имен проектировщиков!)        │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   МИКРОСЕРВЕР (Cloudflare Workers / VPS)               │
│                                                                        │
│ 1. Проверяет факт оплаты по токену в ЮKassa / Prodamus                 │
│ 2. Модуль docxGenerator собирает чистовой .docx за 50 мс               │
│ 3. Отдает готовый бинарный поток байтов на скачивание                  │
└────────────────────────────────────────────────────────────────────────┘
```
* **Плюсы:** Модуль `docxGenerator.ts` **физически отсутствует на компьютере пользователя**. Украсть его или взломать невозможно в принципе. Даже если конкурент скопирует весь фронтенд, он получит лишь экранный калькулятор без возможности выгрузить том для Экспертизы.
* **Приватность:** На сервер уходит массив обезличенных цифр, не подпадающий под коммерческую тайну или персональные данные.

---

### ВАРИАНТ 2. Бинарный анклав Wasm на Rust с Zero-Knowledge привязкой
> **Срок внедрения:** 1–2 недели  
> **Степень защиты:** 99.8% (Уровень коммерческого закрытого софта)  
> **Где применяется:** Полный Air-Gap без передачи даже обезличенных цифр

```
┌────────────────────────────────────────────────────────────────────────┐
│                        БРАУЗЕР КЛИЕНТА (ОФЛАЙН)                        │
│                                                                        │
│ 1. Браузер вычисляет SHA-256 хеш от кабельного журнала Excel:          │
│    Hash = e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b...             │
│ 2. При оплате 990 ₽ на сервер уходит ТОЛЬКО этот 32-байтный хеш        │
│    (На сервер ушло 0 байт схемы объекта!).                             │
│ 3. Сервер подписывает хеш приватным ключом Ed25519 и возвращает билет: │
│    Ticket: { hash: "e3b0...", signature: "0x9f..." }                  │
│                                                                        │
│ 4. WASM BATCH CORE (Rust):                                             │
│    - Зашит публичный ключ Ed25519;                                     │
│    - Проверяет математическую подпись билета;                          │
│    - Сверяет хеш проекта с хешем в билете (защита от Replay-атаки);     │
│    - Внутри бинарника собирает OpenXML и снимает водяной знак.         │
└────────────────────────────────────────────────────────────────────────┘
```
* **Плюсы:** Решает проблему СБ — восстановить проект из SHA-256 математически невозможно. Билет Васи невозможно использовать для чужого проекта в Telegram-чате (другой файл = другой хеш = отказ).

---

### ВАРИАНТ 3. Корпоративный Desktop (Tauri / Bytenode V8)
> **Срок внедрения:** 3–4 рабочих дня  
> **Степень защиты:** 99.9%  
> **Где применяется:** Корпоративные B2B-лицензии для проектных институтов (24 900 ₽/год)

* **Как работает:**
  * Веб-приложение компилируется в нативный Windows EXE через фреймворк **Tauri** (на Rust).
  * Код JavaScript компилируется в закрытый бинарный байткод виртуальной машины V8 (`.jsc` через Bytenode).
  * Приложение переносится на защищенный компьютер без интернета на флешке.
* **Лицензирование:**
  * Офлайн-активация файлом `LICENSE.KEY`, подписанным ключом Ed25519 с привязкой к ИНН проектного института и сроку действия.
  * Работа в 100% глухом офлайне без сетевых адаптеров. Идеально для закрытых НИИ и оборонных институтов.
